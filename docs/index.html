How it works: the mental model

Seven layers that lie to each other

Every WordPress speed tutorial gives the same tips: install a cache plugin, use WebP, lazy-load images. The site in this case study had all of that and still scored 52 on mobile. The problem is never one tip: every layer can undo or hide the work of the previous one. You optimize the HTML variant the real visitor receives, not "the site".

The working loop

Never skip a step

The trap catalog

10 production-earned gotchas

All hit in production, the ones no tutorial mentions.

01

Free-tier CDNs cache one variant per URL

No device split, no Accept negotiation. HTML-level <picture> is the only cache-safe WebP path.

02

Mobile cache off poisons the CDN

Mobile visitors get the raw page and the CDN serves it to everyone.

03

Optimizers trample each other

The page cache saves its buffer before the image plugin rewrites <picture>.

04

Exclusion lists collide

data-no-lazy in the image plugin's list: the hero escaped lazy-load and silently lost WebP.

05

URL-keyed caches never show up in staging

Remove-Unused-CSS stores CSS per production URL. Regenerate before the cutover.

06

Inherited zone config bites years later

A legacy "Cache Everything" rule + 1-year browser TTL froze browsers on old HTML.

07

rsync --delete erases generated artifacts

Stray .webp files vanish on deploy. Every derived asset must live in the repo.

08

The config says one thing, the bytes another

Always grep the served HTML. One grep beats ten admin screens.

09

Field metrics have 28 days of inertia

CrUX takes up to a month to reflect a fix. Write down the fix date.

10

Ads are the mobile ceiling

Eager AdSense costs 20 to 30 lab points. Delaying it is a revenue decision: run it as an experiment.

Install (Claude Code)

Drop the skill into any project

bash

mkdir -p .claude/skills/wp-render-optimization
curl -o .claude/skills/wp-render-optimization/SKILL.md \
  https://raw.githubusercontent.com/gmangabeira/wp-render-optimization/main/SKILL.md

Then ask Claude Code things like:

  • "My WordPress LCP is 6s on mobile, diagnose it"
  • "Audit my site's cache headers"
  • "Why does PageSpeed mobile score way lower than desktop?"

No Claude Code? SKILL.md is plain markdown and works as a checklist for humans. The skill assumes WordPress + a page cache (WP Rocket or similar) + a CDN (Cloudflare or similar), with curl, a PageSpeed Insights API key and SSH access.

Verification playbook

Run after every change

bash

# 1. Is the served variant the optimized one? (repeat with a mobile UA and via --resolve at the origin)
curl -s https://SITE/ -A "Mozilla/5.0 (Macintosh)" | grep -c "rocketlazyloadscript"   # delay active?
curl -s https://SITE/ | grep -o '<img fetchpriority[^>]*' | head -1                     # hero eager?

# 2. Cache headers correct?
curl -sI https://SITE/                       # HTML: short max-age (<=600), HIT/MISS at the CDN
curl -sI https://SITE/path/static.css        # static: max-age=31536000, immutable
curl -sI https://SITE/wp-json/wp/v2/posts    # API: DYNAMIC/BYPASS (never cached)

# 3. Purge -> warm -> measure 3x -> median (never a single sample, never a cold edge)

Acceptance checklist

  • LCP 2.5 s or less, mobile lab
  • CLS = 0, TBT under 200 ms
  • HTML 600 s or less browser TTL, static 1 year immutable
  • REST and admin bypassed, purge-on-publish tested
  • Identical page for mobile and desktop, no double download of the LCP image
Declare victory on one sample? Never. Ad-auction variance is plus or minus 20 mobile points.

Never do this

  • Optimize without a saved baseline
  • Change two things between measurements
  • Trust staging for URL-keyed behavior
  • Long browser TTL on HTML
  • Delay a consent/CMP script
  • Switch hosting while TTFB is healthy
